## Files and facts

- e2e: `npm run test:e2e` (build, then Playwright on port 3100). Runs serially, one worker, phone then desktop, with one throwaway user. A test that needs a clean state must reset it itself (the Copy yesterday test deletes the user's meals on yesterday and today first). Admin inserts into `calorie_targets` need `guest_draft_id`.
- To prove a test catches a bug: switch the fix off, `npx next build`, run the one test with `-g`, then restore.
- During the name save, the server log shows supabase-js's "Using the user object as returned from supabase.auth.getSession()" warning. It did not fail anything. Its cause was not checked.
- Database tests: `npm run test:db`. To mirror CI without touching local data: copy `supabase/` to the scratchpad, change `project_id` and ports (5432x to 5532x), `npx supabase db start --workdir <copy>`, `npx supabase test db --workdir <copy>`, `npx supabase stop --no-backup --workdir <copy>`.
- Never run `npx supabase db reset --local` without asking: local has 4 auth users that may be the owner's.
- The Supabase CLI is linked to **rvfit-prod**. Only use `--local`. Never run `db push` or `config push`.
- Any new user table needs a row limit, a test in `01_privileges` (the table count is 12), and exact grants.
- Files are CRLF in git (autocrlf). The Edit tool is safe. Python is not installed; use Node or the Edit tool for scripted edits.
