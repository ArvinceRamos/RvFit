## Files and facts

- Server data: `src/lib/dashboard-data.ts`, `week-data.ts`, `progress-data.ts`, `meal-days-data.ts`. Pages read `requestClock()` for `today`, `now` and `timeZone`. Format moments (timestamps) with `timeZone`; format calendar dates from their parts with no zone.
- Nav: `src/lib/nav.ts` (`signedInNavItems`, `isActiveSection`), `src/components/signed-in-nav.tsx` (`SignedInNav`, `SignedInTabBar`), `src/components/frame-shell.tsx`. Anything fixed to the bottom on phones must sit above `--tab-bar-space`.
- Browser checks: `npm run build`, then a temporary `prod-check` entry (`npx next start -p 3100`) in `.claude/launch.json`, reverted afterwards (`git checkout -- .claude/launch.json`). When the browser pane is hidden, full loads of streamed pages do not hydrate; load /privacy, then use `window.next.router.push(...)`. Server HTML can be checked with `fetch(path)`.
- Local test user: a Node script in the scratchpad using the admin API (`npx supabase status -o json` gives `API_URL` and `SERVICE_ROLE_KEY`; load `@supabase/supabase-js` with `createRequire` from the repo). Keep credentials in the scratchpad, never in chat or the repo, and delete the user afterwards. The local stack signs tokens with ES256.
- The Supabase CLI is linked to **rvfit-prod**. Only use `--local`. Never run `db push`.
- Files are CRLF in git. Strip `\r` before scripted edits, or use the Edit tool. Long inline node heredocs can break the Bash tool; write scripts to the scratchpad. `git rm` of the last handoff file removes `docs/handoffs/`, so write the next handoff first.
- Checks: `npm run typecheck`, `npm run lint`, `npm test` (764 tests at the end of Phase 4), `npm audit --omit=dev`, `npm run build`.
