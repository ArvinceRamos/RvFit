## Files and facts

- Database tests: `supabase/tests/database/01`–`04`. Each runs in one transaction and is rolled back. Act as a user with `set local role authenticated` and `set local "request.jwt.claims" to '{"sub": "…"}'`. As a user, RLS hides other users' ids, so note them before switching.
- To mirror CI without touching local data: copy `supabase/` to the scratchpad, change `project_id` and the ports (5432x to 5532x), run `npx supabase db start --workdir <copy>` and `npx supabase test db --workdir <copy>`, then `npx supabase stop --no-backup --workdir <copy>`.
- Never run `npx supabase db reset --local` without asking: local has 4 auth users that may be the owner's.
- e2e: `npm run build`, then `npx playwright test`. Global setup refuses non-local Supabase. Test files end in `.e2e.ts` so Vitest skips them. Use `page.route` with `route.fetch()` then `route.abort()` to simulate a lost reply.
- Row limits (placeholders) are in the migration header and the RUNBOOK. Any new user table needs a limit, a test in `01_privileges` (the table count is 12), and grants that list exactly what the app uses.
- The Supabase CLI is linked to **rvfit-prod**. Only use `--local`. Never run `db push` or `config push`.
- Files are CRLF in git. Strip `\r` before scripted edits, or use the Edit tool. Write long scripts to the scratchpad.
